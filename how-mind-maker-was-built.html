Build notes

How Mind Maker's guide was built

Mind Maker is a small app where children build tiny AI minds out of plain sentences and watch them make art, judge their own work, and slowly get better. This page is about the layer added on top of it: a guided voice demo. It walks a first-time visitor through the whole app out loud — moving a spotlight from one part to the next, running a real round so you can watch a mind make something and learn from it, answering whatever you ask along the way, and carrying out actions for you when you'd rather it just did the thing. The app was already there; the guide is what makes it introduce itself.

GUIDENone of this is secret code. It's all just plain words that you can change.
GUIDEIn a round, the mind makes something, looks at it, and learns a lesson for next time.

How the guide got better

One watched pass at a time

The guide began as a script — a set of stops, each one moving to a screen, lighting up a part, and saying a line out loud. Then it grew. It can now answer whatever you ask and act on it: opening a mind, running a round, or setting up a Show & Tell because you said so, working out what you meant and doing the thing.

Almost all of the work after that was making it feel right to watch and hear — and that can only be judged by running it. Does the voice keep time with the picture as a round unfolds? Does the spotlight move with the words, or leap ahead of them? Does it ever congratulate you for something it just did itself, or walk you into a screen with nothing on it? None of that is visible in the code. It only shows up when the thing is actually speaking and drawing in front of you.

So every pass looked the same. Run the guide for real. Watch it, listen to it, and send back a screenshot and the app's own debug log. Find what actually happened — usually not the obvious culprit. Make the change, then write a small headless test so the next change can't quietly undo it. The guide improved in small, watched increments: narration re-timed so it never falls behind the paint; the spotlight driven from the same queue as the voice, so the light and the words move together; a snapshot taken after the guide's own moves, so only your changes get read back as yours; a once-empty Show & Tell that now quietly gets a couple of minds ready rather than stranding you; and a memory of what it has already shown you, so coming back a second time covers only what's new.

Which is the shape of the whole thing: the tests can prove an action fired and a mind was made and the spotlight visited the right places in the right order. Whether it feels in time, whether a sentence runs too long to hear comfortably, whether any of it lands warmly for a nine-year-old — that stayed with a person's eyes and ears.

One HTML file. No build step, no framework, no runtime dependency but the language model the guide talks to. Vanilla JavaScript, the browser's own Web Speech API for the voice, and a lineage that runs back through Logo and turtle graphics to Seymour Papert's idea that you understand a thing most deeply by building it.

Made by a person and an AI, one watched edit at a time.

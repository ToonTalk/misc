FIELD NOTES · PROCESS

How Tiny Mind was made

The idea, the spec, and the division of labor between a human, Claude on claude.ai, and Claude Code — including the parts that went wrong and what they taught.

These notes were drafted by Claude from inside the design conversation, at Ken Kahn's request — one participant's view of a joint process, checked against the project's own reports and test suites. Ken's own account is in his post.

THE IDEA

The project began not with an app but with a gap analysis. Reviewing several years of Ken's AI experiments, one axis stood out as unexplored: the model as a constrained participant inside a microworld rather than as builder or conversationalist. Crossed with two long-standing interests — constructionist learning in the Papert tradition, and mechanistic interpretability — it suggested a glass-box language model children could train and then dissect. TinyStories made it feasible: if a 260,000-parameter model can tell story-shaped tales, it is small enough to train in a browser and small enough to open.

One design move carried the scientific weight: the child's invented character. Because "Zog" did not exist until the child created him, no claim about where the model stores Zog can be recited from any literature — every explanation the software (or its AI) offers must be derived, and a child can falsify it. The app's epistemology follows from that: highlights are clues; switching a component off and measuring the damage is proof.

FROM CONVERSATION TO SPEC

Design happened in dialogue on claude.ai and was frozen into short kickoff documents — one per building session — recording the locked decisions: two models (a 260K trainee whose entire 512-piece alphabet fits on one screen, and a 15M specimen for the microscope); binary formats verified against source rather than memory; a rule that model code stay free of any web-page dependencies so the same functions run in the app and in the test suite. Each kickoff ended with explicit gates: measurable pass/fail conditions that had to hold before features were built on top.

GATES BEFORE FEATURES

The first building phase produced no visible app at all. It produced proofs: the hand-written JavaScript model reproduces the reference C implementation's output exactly, token for token; the hand-rolled training code passes a finite-difference gradient check to around one part in ten million; and a sweep of training runs established the numbers the Nursery's pedagogy now rests on — the learning curve flattens around a hundred steps, mixing old stories into training prevents forgetting in a dose-dependent way, and training past the flat point makes held-out surprise rise again. That last curve became a feature twice over: the "parroting" badge, and a time-machine arc deliberately trained into the overfitting regime so children can scrub through the mistake.

WHO DID WHAT

KEN — set the goals and the taste; made every locked decision; ran all local builds and tests; carried files and reports between sessions; tested each build as a user, which found things nothing else did.
CLAUDE ON CLAUDE.AI — design partner and spec author; wrote the kickoff documents; ported the apps into the claude.ai artifact sandbox (a saga of its own: discovering by experiment that the sandbox blocks worker threads, downloads from nested frames, and all third-party network calls); and later served as independent auditor of builds it did not make.
CLAUDE CODE — the engine room: the model, trainer, and instrument code; the test suites (roughly seventy assertions at last count, run as a "fingerprint" before any handoff); the tools that generate training-arc snapshots and assemble releases from source.

The connective tissue mattered as much as the roles: every handoff carried a kickoff document in, and a report plus a test-count fingerprint out. Sessions routinely disagreed with their instructions — productively. One session, told to edit the "release files," read the test suite, deduced those files were build outputs, and asked permission to override its own kickoff. It was right.

THINGS WENT WRONG, USEFULLY

Multi-session AI collaboration has a characteristic failure class: provenance — knowing which bytes are canonical and where a change actually lives. The project hit it repeatedly. A build tool was lost when the session that wrote it ended; it was reconstructed from the built artifact itself, with a byte-identical round-trip as proof of correctness. A finished feature was reported missing twice — once because it was hidden behind data that hadn't loaded, with no empty state to say so; once because the file-ingest code recognized arc packs only before unzipping, and packs ship as zips. Each incident produced a rule that is now infrastructure: generated files carry a stamp saying so; every gated feature must be discoverable in its gated state; builds ship a self-verification block; and acceptance tests must feed the software the actual shipped bytes, not a convenient approximation.

THE SCIENCE THAT FELL OUT

Building the Hunt honestly forced real findings. Single neurons and single attention heads almost never proved out as the home of a fact — but ablating a coordinated group collapsed it: knowledge in even this tiny model is distributed, which the app now teaches with a choir metaphor before the first busted clue. A scoring bug turned into a lesson about tokenization: multi-piece words looked "unknown" because per-piece probabilities were being multiplied. And a control experiment — swap the character's name and re-ask — separates facts that are genuinely about the character from mere word-pattern collocations. None of this was in the spec; all of it is now in the app.

WHAT THE AI MODELS ADDED, HONESTLY

The frontier-model contribution wasn't typing speed. It was holding a long spec faithfully across a large build; designing instruments that are honest rather than merely plausible (a wrong-but-convincing attention visualization is worse than none); arguing back when the spec was wrong; and auditing — including one Claude extracting and gradient-checking another Claude's hand-written backpropagation and finding it correct to seven decimal places. The failures were real too, and the process above exists because of them.
